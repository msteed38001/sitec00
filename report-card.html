The Data Quality Report Card

If you have 75,000 SKUs, you don't need a cloud cluster to tell you if the data is clean. You need a weighted, deterministic audit.

The Report Card is a pure Python CLI tool that runs a standardized inventory sheet (in SQLite) through a series of TOML-defined validation rules. It doesn't just check for nulls. It applies business logic, calculates weighted severity scores, and generates a visual report card that tells you exactly where your data is failing.

No Databricks. No Pandas. Just raw Python running against a local database.

Weighted Severity Scoring

Not all data errors are equal. A missing barcode breaks counter scanning (Critical). A missing manufacturer name just makes search harder (Warn). The Report Card applies weights and penalties to every rule, so you know exactly which errors are costing you money and which are just annoying.

Grouped by Business Segments

The rules are organized into business segments: Structural, Identity, Classification, Commercial, Regulatory, and Attributes. This lets you see the health of your data at a glance. If Classification is failing at 46%, you know your Ariba integration is in trouble.

The Output

The tool generates a summary dashboard at the top, showing the top findings by violation count, and then dives into a detailed breakdown of every rule.

The Architecture

The Report Card is built on the same Micro-Kernel philosophy as everything else. The Python code (main.py, rules.py, score.py, charts.py) is completely generic. The business logic lives entirely in the TOML configuration.

You can define custom rules, set weights, and add new segments without touching a single line of Python. If you need a new format check or a new business rule, you just add it to the TOML.

How does the scoring work?

Every rule has a weight and a penalty. If a rule fails, its penalty is applied to the field. If multiple rules fail on the same field, the penalties stack with a multiplier. The final score is a weighted average of all field scores. A score of 100 means the field is perfect. A score of 0 means it's completely broken.

Why not just use Pandas?

Pandas is great for ad-hoc analysis, but it's terrible for deterministic, repeatable audits. It silently coerces data types, it drops rows with hidden characters, and it requires a massive dependency tree.

This tool uses raw SQLite and pure Python dictionaries. It is fast, it is deterministic, and it runs on an 8GB laptop. It will still run exactly the same way in 10 years.
